# Pre-release methodology & claims audit (2026-08-25)

Companion to `falsification.txt` (the empirical falsification run). Before
v2.0.0 was published, the measurement methodology and every public claim
were attacked by an adversarial review: 14 findings were raised, each was
then handed to an independent verifier whose job was to refute it.

**Outcome: 11 of 14 refuted; 2 documentation fixes; 1 informational note;
no measurement defects.**

## Refuted (finding — why it failed)

1. *fp16 trials could be flattered by GradScaler-skipped optimizer steps* —
   empirically zero skips in the timed regime (falsification.txt F3).
2. *channels-last conversion measured differently than delivered* —
   misread the code; residual effect negligible.
3. *Static resident batch flatters CUDA-graph candidates vs real loops* —
   empirically refuted: winners reproduce within rounding in real
   fresh-batch loops (falsification.txt F1).
4. *cudnn.benchmark bundled into candidates but denied to baselines is an
   undisclosed confound* — the baseline definitions are labelled; the
   reference rows use PyTorch defaults deliberately.
5. *Warmup-stabilisation heuristic near-vacuous* — harm scenarios
   contradicted by the reproduction data.
6. *"Structurally incapable of returning a slower config" overstates a
   protocol-scoped guarantee* — each proposed failure path fails against
   the code.
7. *Compile costs reflect warm in-process Inductor caches* — true
   mechanics, but costs are reported per-trial as measured and the search
   cost story does not depend on cold caches.
8. *Strict-fp32 column is a foregrounded strawman; workloads flattering* —
   already disclosed in the README's footnotes.
9. *"AMP loses on tiny models" only true for fp16* — bf16's 0.48% edge is
   ~6x below the noise floor; the sentence stands.
10. *ResNet-50 returned config was not the raw-fastest trial* — correct
    observation, but the 3% noise-floor winner rule is documented; see
    the fix list below for the wording this still prompted.
11. *"max-autotune compiles can take 1-4 min" unsupported* — supported by
    the committed compile_s values.

## Confirmed → fixed

1. README claimed compile-default "is the right call for ResNet-50" while
   the committed table shows reduce-overhead winning by 3.9% — reworded.
2. Wheel metadata declared `Requires-Python >=3.7` against the tested 3.10
   floor — fixed before upload.

## Informational (not an error)

* The search's own baseline trial (8.95 ms) and the separately measured
  reference baseline (8.96 ms) both appear in the JSON; each quoted number
  matches its own source (3.83x vs 3.84x).

## Post-publish follow-up (v2.0.1 docs)

A second audit of the published README upheld three wording-fidelity
issues, fixed in v2.0.1: the report excerpt is now generated by rendering
the committed JSON through `Report.__str__` (it previously omitted the
break-even line and used different column widths, though every number
matched); "within 4% of optimal" is now stated as "within 4% of the
tuner's pick" with the raw-fastest trial and noise-floor rule spelled out;
and the falsification drift is quoted per-model (−0.1%/+1.3%/+1.5%,
i.e. ≤1.6% allowing for rounding) instead of a flat "within 1.5%".
